# Решение тестового задания (Денис Садовой)

Задача решения - предсказать вероятность того, что изображение текстовой строки
повёрнуто на 180°.

> **Результат на лидерборде: `1 - Brier Score = 0.99208426`**
>
> Brier Score: `0.00791574`

Финальный пайплайн объединяет специализированные модели ориентации, multi-crop
обработку длинных строк и признаки трёх компактных OCR-моделей. Все этапы
воспроизводятся через DVC, а итоговые файлы проверяются по SHA-256.

## 1. Подготовка окружения

Для запуска необходимы:

- Python 3.12;
- менеджер зависимостей [`uv`](https://docs.astral.sh/uv/);
- конкурсная тестовая выборка.

Установите зафиксированные зависимости:

```bash
uv sync --frozen
```

После распаковки конкурсного архива структура данных должна выглядеть так:

```text
data/test/
├── sample_submission.csv
└── test/
    └── images/
        ├── test_00000.png
        ├── test_00001.png
        └── ...
```

В `data/test/test/images` должно находиться ровно 20 000 PNG-файлов. Имя файла
без расширения должно совпадать с `image_id` в `sample_submission.csv`.

## 2. Быстрое формирование сабмита

Если предсказания базового ансамбля и трёх OCR-моделей уже рассчитаны, финальный
сабмит формируется одной командой:

```bash
uv run python scripts/create_submission_ocr_v5_meta.py
```

Для этого быстрого шага `data/test` не требуется. Порядок и формат `image_id`
берутся из `submission_three_model_two_regime_tuned.csv`, а все модельные
признаки — из сохранённых OCR-кешей. Конкурсные изображения нужны только для
полного пересчёта предсказаний через `dvc repro`.

Скрипт обучит финальную логистическую регрессию на Yandex-валидации и создаст:

```text
submission_ocr_v5_meta_yandex_selected_b8.csv
submission_ocr_v5_meta_yandex_selected_b8.json
```

Ожидаемая SHA-256 финального CSV:

```text
9580d7080b3e19c0b3e01e80e2c291743739caa2964a6dd049bbb9cc99226ffd
```


## 3. Полное воспроизведение через DVC

Чтобы полностью воспроизвести решение из скриптов и конкурсной тестовой
выборки, выполните:

```bash
uv run dvc repro
```

DVC последовательно:

1. Проверит Python 3.12 и зафиксированную версию OpenCV.
2. Скачает открытый OCR-датасет Яндекса.
3. Сформирует валидационную выборку из 553 строк.
4. Рассчитает базовый ансамбль и multi-crop признаки.
5. Запустит три OCR-модели на Yandex с `batch_size=32`.
6. Рассчитает базовый ансамбль для 20 000 тестовых изображений.
7. Запустит три OCR-модели на тесте с `batch_size=8`.
8. Обучит финальную метамодель и сформирует сабмит.
9. Проверит контрольные суммы всех важных артефактов.

Успешное воспроизведение заканчивается сообщением:

```text
Все артефакты совпали с эталонными SHA-256.
```

Это означает, что промежуточные файлы и финальный сабмит совпали с эталоном
побайтово. Полное описание графа находится в
[`DVC_PIPELINE.md`](DVC_PIPELINE.md).

Пайплайн рассчитан на CPU. На использованном процессоре полный запуск занял
около 26 минут. Модели Paddle можно перенести на GPU, что должно заметно
сократить время инференса, но текущая эталонная сборка и её контрольные суммы
зафиксированы для CPU.

## 4. Валидационная выборка

Для обучения и выбора финальной конфигурации использовался открытый
[`rus_ocr_in_the_wild_dataset`](https://github.com/yandex-cloud/ocr/tree/master/ocr_comparison/rus_ocr_in_the_wild_dataset)
от Yandex Cloud.

Из реальных фотографий автоматически формируются 553 длинные текстовые строки.
Половина изображений воспроизводимо поворачивается на 180°, поэтому правильные
ответы известны без ручной разметки конкурсного теста.

В выборку входят:

- чистые строки;
- умеренно ухудшенные строки;
- сильно ухудшенные, но читаемые строки;
- слегка искривлённый текст.

Для защиты от утечки используется **5-fold source-grouped валидация**: примеры
из одной исходной фотографии не попадают одновременно в обучение и проверку.
Средний результат выбранной конфигурации на пяти фолдах — около
**`1 - Brier Score = 0.985`**.

Формирование выборки полностью детерминировано. Основной seed — `20260926`, а
ориентация изображений задаётся с seed `20260927`.


## 5. Базовый ансамбль

Первый уровень решения состоит из трёх моделей, специально предназначенных для
определения ориентации текста:

- `PP-LCNet_x0_25_textline_ori`;
- `PP-LCNet_x1_0_textline_ori`;
- классификатор ориентации `RapidOCR`.

Обе PP-LCNet запускаются на исходном изображении и его копии, повёрнутой на
180°. Такой flip-TTA делает прогноз устойчивее. Вероятность `PP-LCNet x1.0`
дополнительно калибруется температурой, после чего сигналы трёх моделей
объединяются.

### Multi-crop для длинных строк

При большом отношении ширины к высоте обычный ресайз слишком сильно сжимает
текст и стирает форму букв. Поэтому для строк с `width / height >= 10` ансамбль
отдельно обрабатывает три фрагмента:

- левый;
- центральный;
- правый.

Предсказания фрагментов усредняются и калибруются. Такой режим позволяет
сохранить детали очень длинных надписей.

## 6. Три OCR-модели

Второй источник признаков — три мобильных распознавателя PaddleOCR v5:

- `cyrillic_PP-OCRv5_mobile_rec`;
- `eslav_PP-OCRv5_mobile_rec`;
- `en_PP-OCRv5_mobile_rec`.

Каждая модель распознаёт исходную и повёрнутую версии изображения. В правильной
ориентации OCR обычно выдаёт более высокую уверенность и более правдоподобный
текст.

В финальную модель передаются:

- уверенность OCR в обеих ориентациях;
- разница уверенностей;
- разница длины распознанного текста;
- доля кириллических символов;
- оценка текста символьной языковой моделью;
- расхождение между тремя OCR;
- базовая вероятность ансамбля;
- отношение ширины изображения к высоте.

Три языковые модели дополняют друг друга на кириллице, смешанных надписях,
латинице и декоративном тексте, где одной модели ориентации часто недостаточно.

## 7. Финальная метамодель

Финальная модель — компактный пайплайн
`StandardScaler + LogisticRegression`. Он обучается на 553 примерах
Yandex-валидации и объединяет базовую вероятность с OCR-признаками.

Зафиксированные параметры:

| Параметр | Значение |
| --- | ---: |
| `C` | `0.3` |
| `class_weight` | `balanced` |
| `random_state` | `20260927` |
| Температура итоговой вероятности | `0.42` |

Логистическая регрессия почти не увеличивает стоимость инференса, но улучшает
калибровку вероятностей под Brier Score. Модель сохраняет высокую уверенность на
простых строках и осторожнее оценивает сложные случаи.

## 8. Почему решение получилось сильным

- **Высокое качество:** `1 - Brier Score = 0.99208426` на лидерборде.
- **Компактная архитектура:** используются мобильные PP-LCNet и PP-OCRv5, а
  финальная модель является обычной логистической регрессией.
- **Отдельная обработка длинных строк:** multi-crop сохраняет детали текста при
  большом отношении ширины к высоте.
- **Сигнал из распознанного текста:** ориентация оценивается по изображению,
  уверенности OCR и правдоподобию результата распознавания.
- **Воспроизводимость:** версии библиотек, seed, размеры пакетов и граф
  вычислений зафиксированы, а результат проверяется по SHA-256.
- **Продолжение после остановки:** OCR-кеши пропускают уже обработанные
  `image_id`, поэтому длительный CPU-инференс можно безопасно возобновить.
