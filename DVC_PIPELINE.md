# Полное воспроизведение решения через DVC

## Что должно лежать в проекте до запуска

Для запуска с нуля нужны исходники проекта и тестовые данные:

```text
scripts/
data/test/sample_submission.csv
data/test/test/images/*.png
pyproject.toml
uv.lock
dvc.yaml
params.yaml
```

Каталоги `data/train`, `outputs`, кеш моделей и готовые сабмиты не нужны.
Они будут созданы автоматически.

## Одна команда

Из корня проекта выполните:

```bash
uv run dvc repro
```

`uv` создаст окружение по `uv.lock`, включая DVC и
`opencv-python==5.0.0.93`. Затем DVC выполнит все этапы в правильном порядке.
Первый этап переустановит OpenCV 5 последним wheel-пакетом: это необходимо,
потому что обязательный `paddlex[ocr-core]` также устанавливает
`opencv-contrib-python==4.10.0.84` в тот же модуль `cv2`.

## Что делает пайплайн

1. Восстанавливает OpenCV 5 после `uv sync`, затем проверяет Python 3.12,
   `opencv-python==5.0.0.93` и фактически импортированный `cv2==5.0.0`.
2. Скачивает зафиксированный коммит открытого OCR-датасета Яндекса.
3. Формирует 553 длинные строки с сидом `20260926`.
4. Считает базовый ансамбль и multi-crop признаки на Yandex-валидации.
5. Запускает три OCR-модели на Yandex-валидации с `batch_size=32`.
6. Строит базовый ансамбль для 20 000 тестовых изображений.
7. Запускает три OCR-модели на тесте с `batch_size=8`.
8. Обучает зафиксированную метамодель на 553 строках Яндекса.
9. Формирует финальный сабмит и проверяет SHA всех важных файлов.

Финальный файл:

```text
submission_ocr_v5_meta_yandex_selected_b8.csv
```

Ожидаемая SHA-256:

```text
9580d7080b3e19c0b3e01e80e2c291743739caa2964a6dd049bbb9cc99226ffd
```

Успешное завершение этапа `verify_submission` означает, что сабмит и
промежуточные кеши совпали с эталоном побайтово.

## Повторный запуск с нуля

DVC повторно выполняет только изменившиеся этапы. Чтобы принудительно пройти
весь граф заново, используйте:

```bash
uv run dvc repro --force
```
